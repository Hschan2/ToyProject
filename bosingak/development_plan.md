# 보신각 (BOSINGAK) 개발 계획

> 하나의 종을 울리기 위해 모인 사람들. 누군가는 종을 치고, 누군가는 기도하며, 누군가는 그 순간을 함께 바라본다.

- 프로젝트명: 보신각 (BOSINGAK)
- 프로젝트 유형: 온라인 멀티플레이 소셜 힐링 게임
- 개발 방식: 1인 개발 + AI 바이브 코딩
- 플랫폼: PC 웹 브라우저
- 개발 목표: 최대 100명이 하나의 가상 공간에 접속해 종 치기, 기도, 촛불 들기 등을 경험하는 온라인 힐링 서비스

# 2. 개발 일정

## 개발 일정 개요

개발은 1인 개발과 AI 바이브 코딩을 기준으로 진행한다.

총 30일을 기본 개발 일정으로 설정하며, 각 단계의 완료 여부에 따라 일정이 조정될 수 있다.

| 구분 | 개발 내용 | 기간 |
|---|---|---|
| 1일 차 ~ 2일 차 | 프로젝트 환경 및 기본 구조 | 2일 |
| 3일 차 ~ 5일 차 | 3D 공간 구현 | 3일 |
| 6일 차 ~ 8일 차 | 플레이어 및 이동 시스템 | 3일 |
| 9일 차 ~ 12일 차 | 종 치기 시스템 | 4일 |
| 13일 차 ~ 14일 차 | 기도 및 촛불 시스템 | 2일 |
| 15일 차 ~ 19일 차 | 멀티플레이 시스템 | 5일 |
| 20일 차 ~ 22일 차 | 실시간 날씨 시스템 | 3일 |
| 23일 차 ~ 24일 차 | UI 및 사운드 | 2일 |
| 25일 차 ~ 27일 차 | 통합 테스트 및 최적화 | 3일 |
| 28일 차 ~ 30일 차 | 배포 및 최종 점검 | 3일 |

※ 실제 100명 동시 접속 검증과 네트워크 문제 해결에 따라 일정이 늘어날 수 있다.

# 4. 개발 진행 원칙

1. 하루에 하나의 핵심 목표를 설정한다.
2. AI 코딩 도구에 한 번에 전체 프로젝트를 구현하도록 요청하지 않는다.
3. 기능별로 구현하고 테스트한 뒤 다음 단계로 넘어간다.
4. 기존에 정상 작동하는 기능을 임의로 수정하지 않도록 AI에게 지시한다.
5. 코드 수정 전 현재 프로젝트 구조와 관련 파일을 확인하도록 한다.
6. 각 단계가 완료되면 GitHub에 커밋한다.
7. 무료 라이브러리와 무료 호스팅을 우선 사용한다.
8. 실제 100명 동시 접속은 부하 테스트로 검증한다.
9. 서버에서 중요한 게임 판정과 참여 인원 제한을 관리한다.
10. 시각적 완성도와 안정성을 함께 고려한다.

# 5. 최종 개발 목표

최종적으로 다음과 같은 경험을 제공하는 서비스를 완성한다.

- 최대 100명이 하나의 보신각 공간에 접속한다.
- 플레이어는 지정된 시작 위치에서 생성되고 자유롭게 이동한다.
- 종 앞에서 직접 줄을 잡아야 종 치기에 참여할 수 있다.
- 최대 5명이 함께 종을 칠 수 있다.
- 2명 이상일 때 한 명이라도 타이밍을 놓치면 해당 반동은 실패한다.
- 총 4회의 반동을 성공시키면 종이 울린다.
- 종 치기를 완료하면 자동으로 줄을 놓는다.
- 다른 플레이어는 종을 관람하거나 기도하고 촛불을 들 수 있다.
- 실제 서울의 날씨와 시간에 따라 게임 환경이 변화한다.
- 모든 플레이어가 동일한 종 울림과 환경 변화를 경험한다.
